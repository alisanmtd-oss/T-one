# Shopee expert curriculum

Train by concrete `platform + country_site + store_model + ownership`; use `SEA` only for reporting. Do not advance a module from reading alone: pass its evidence check and regression cases.

| Module | Required outcome | Exit evidence |
|---|---|---|
| C01 Route and identity | Resolve SG/MY/TH/VN/PH/ID/TW/BR, store binding, seller origin, program, fulfillment, ownership, and execution identity. | Complete route or an explicit `blocked_owner_input`; no regional write route. |
| C02 Store programs | Separate local/cross-border, SIP, Direct, global/light-overseas labels, and real authorization scope. | Program classification cites current official terms and real shop evidence where applicable. |
| C03 FBS and logistics | Separate FBS, platform logistics, seller fulfillment, and third-party warehouse. | Site/shop enrollment, warehouse/SKU mapping, SLA, and fee inputs are present or unknown. |
| C04 Listing compliance | Validate product facts, IP, prohibited items, category attributes, media rights, language, parcel data, returns, and mobile-first copy. | Draft contains no invented facts and all write actions remain approval-gated. |
| C05 Pricing and profit | Model currency, fees, tax, logistics, vouchers, affiliate, ads, refunds, COGS, and target margin. | Store/site inputs are sourced; missing values remain unknown. |
| C06 Activities and stacking | Model campaign, discount, voucher, shipping subsidy, bundle, flash sale, and eligibility interactions. | Current site rule and checkout/store evidence; no cross-site extrapolation. |
| C07 Shopee Ads | Separate product/search, video, live, affiliate, and off-platform media. | Store/site Ads identity, eligibility, balance, budget, stop-loss, attribution, and approval. |
| C08 Orders and aftersales | Map orders, SKU, warehouse, carrier, deadlines, buyer messages, returns, and refunds. | Authorized data or labeled import; external actions are individually confirmed. |
| C09 Settlement | Reconcile revenue, platform deductions, ads, vouchers, affiliate, logistics, tax, refunds, and payout. | Store-scoped settlement evidence and variance explanation. |
| C10 Platform-native AI | Audit available Shopee AI/chat/live/listing/media features, accuracy, rights, labeling, and privacy boundaries. | Site/shop feature evidence; terms alone do not prove feature availability. |
| C11 Software integration | Map Open Platform, Seller Centre, Ads, ERP, reports, and T One result writeback. | Tested connector evidence or truthful `available_unconnected`. |
| C12 Learning loop | Deduplicate evidence, expire stale rules, run regressions, log failures, and select next weakest module. | Increment report, passing tests, and updated cursor without rewriting unchanged facts. |
| C13 Category and tenant isolation | Read site/category schema and keep platform/category/tenant/task layers separate across apparel, home, beauty, electronics, food/restricted products, digital goods and machinery. | At least one anonymous non-private_tenant regression per generic capability; missing facts remain unknown and no private_tenant price/media/stock/warehouse/customer fact leaks. |
| C14 Official open-source audit | Verify organization identity from a first-party chain; deduplicate owner/repo+commit/tag; audit README/docs, releases, LICENSE, issues/replies, discussions, PRs, security, commits, dependencies, data and commercial boundaries. | Repository is classified `research_only`, excluded, or proposed for the existing module with exact evidence; no clone/install/run and no official-research-to-Shopee-connector leap. |
| C15 Industry, AI and comment signals | Rotate official industry/AI updates with a professional social/video/forum comment surface; inspect multiple sorts, replies and counterexamples; anonymize clusters and return rule-change leads to official sources. | Actual coverage, filtered noise, conflicts, official rechecks and regressions exist; no personal data, external interaction or popularity-as-truth promotion. |
| C16 Knowledge-package reuse | Start from the exact T One gap; use the English query matrix to compare 2–3 Skills/SDKs/playbooks/SOPs/schemas/evals/ERP or analytics packages; sample one workflow, one failure and three rules; validate only the sampled claims on official deep pages. | At least 50% package-audit share, exact query/fingerprint/license/security/credential/dependency/site scope, one allowed decision, precise merge location, no install/duplicate runtime and generic official introductions below 10%. |

Training priority: blocked safety/identity failures first, then the oldest unverified time-sensitive rule, then the weakest regression module. A module is `learning_only` until it has official evidence, a counterexample, and a passing evaluation; live execution modules also require a real store binding and authorization.
